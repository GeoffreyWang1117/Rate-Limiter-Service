
Benchmark B -- worst-case vs adaptive reservation

  budget            400,000 tokens/minute
  burst             400 requests arriving together
  declared ceiling  4096 output tokens
  workload          prompt ~900 tokens, output log-normal (median 180, sigma 0.9)  [assumption, not a trace]
  per request       5344 tokens declared, 1498 actually used (72.0% of the declaration is never generated)

  worst_case  calibrating ... burst ... done
  adaptive    calibrating ... burst ... done

how much of the burst fits in the budget

        mode  admitted  shed  admitted %  mean held  mean used  held but unused %
  ----------  --------  ----  ----------  ---------  ---------  -----------------
  worst_case        75   325        18.8       5341       1471               72.5
    adaptive       230   170        57.5       1739       1516               12.9

what adaptive gives up for it

        mode  overruns  overrun %  overrun tokens  as % of used
  ----------  --------  ---------  --------------  ------------
  worst_case         0       0.00               0          0.00
    adaptive        29      12.61            6372          1.83

  adaptive admitted 3.07x as much of the burst from the same budget,
  and overran on 29 of 230 admitted requests (12.61%).
  Overruns are charged at commit, so they are paid for -- they are not a way past the budget.
